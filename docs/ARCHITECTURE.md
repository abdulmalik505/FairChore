## Layering

Bottom-up, no cyclic dependencies:

1. **`algorithms/`** — pure functions. Input: dict-of-dicts of scores and
   an optional capability matrix. Output: an assignment dict. No I/O, no
   database, no Flask. Called from three places: `evaluation/`, `backend/app.py`,
   and `tests/`.
2. **`simulation/personas.py`** — generates scenarios and scores for the
   offline sweeps. No dependency on `backend/` or the database.
3. **`evaluation/`** — consumes `algorithms/` + `simulation/` to produce
   report-ready artefacts in `results/`. No dependency on `backend/`.
4. **`backend/app.py`** — the Flask app. Imports `algorithms/` for allocation
   but not `simulation/` or `evaluation/`. Talks to PostgreSQL via `psycopg2`.
5. **`frontend/src/`** — React SPA that talks to `backend` over HTTP.
6. **`tests/`** — split four ways: unit/integration tests import
   `algorithms/` and `simulation/` directly; db/api tests spin up a
   temporary `fairchore_test` database and hit the Flask test client.

## Two-phase allocation flow

```
POST /api/households/<id>/allocate
   ├─ fetch members (ordered by total_burden_accumulated ASC)
   ├─ fetch UNASSIGNED active chores (completed_at IS NULL filter)
   ├─ compute historical loads → AdjustedScore = preference + λ · hist
   ├─ run chosen algorithm on adjusted scores + capability matrix
   ├─ compute metrics on ORIGINAL preferences
   └─ return DRY-RUN preview  (nothing written)

POST /api/households/<id>/allocate/confirm
   ├─ one INSERT per chore into assignment_history (shared confirmed_at)
   ├─ one INSERT into allocation_results (scores_json + metrics_json)
   └─ UPDATE users.total_burden_accumulated

POST /api/assignments/<id>/complete  (assignee only)
   └─ UPDATE assignment_history SET completed_at = NOW()
```

A *round* is the set of history rows that share a `confirmed_at` timestamp.
Uncompleted chores from earlier rounds remain in `assignment_history` with
`completed_at IS NULL` and are excluded from the next `/allocate` call.

## Data model (condensed)

```
users(id, username, email, password_hash, total_burden_accumulated NUMERIC(12,2))
households(id, name, join_code, admin_id)
household_members(household_id, user_id)
chores(id, household_id, title, description, is_active)
burden_scores(user_id, chore_id, score INT, is_capable BOOL, UNIQUE(user,chore))
assignment_history(id, user_id, chore_id, burden_at_time NUMERIC(10,2),
                   algorithm_used, date_assigned, completed_at)
allocation_results(id, household_id, round_ts UNIQUE, algorithm,
                   scores_json JSONB, metrics_json JSONB)
```

## Build-time and run-time dependencies

- Python 3.11+, `psycopg2-binary`, `Flask`, `python-dotenv`, `matplotlib`,
  `pytest`, `pytest-cov` (listed in `requirements.txt`).
- Node 18+, `create-react-app`/`react-scripts` 5, React 18 (listed in
  `frontend/package.json`).
- PostgreSQL 14+ for both dev (`fairchore`) and the pytest test DB
  (`fairchore_test`, created and torn down per session).
